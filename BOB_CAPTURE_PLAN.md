# Bob 2.0 Evidence Capture Plan

Submission requires: (1) code/files where Bob 2.0 assisted, (2) screenshots of Bob's task session summaries. Both are graded as hard requirements, not optional polish — capture as you go during the 48 hours, not retroactively at the end.

## Why a plan, not just "remember to screenshot"
Under 48-hour time pressure, evidence capture is the first thing skipped when things get stressful near a deadline. A short checklist tied to specific build milestones removes the judgment call in the moment.

## Capture checklist (tie each to a build milestone, not a time of day)

- [ ] **Kickoff**: screenshot Bob 2.0's first session/onboarding screen (proves access + start time).
- [ ] **Hotspot generation**: for each of the 8 Axios hotspots, screenshot the Bob session where it generates the question/answer/citation for that hotspot. (8 screenshots minimum — this is the core "meaningful use of Bob" evidence.)
- [ ] **Answer evaluation logic**: screenshot a session where Bob evaluates a free-text answer against ground truth and returns a verdict + correction.
- [ ] **Adaptive follow-up**: screenshot a session showing Bob generating an easier/harder follow-up based on a wrong/right answer.
- [ ] **Session summary synthesis**: screenshot Bob synthesizing a full transcript into the end-of-session summary — this doubles as both evidence AND a demo artifact (per NOTES.md).
- [ ] **Any code Bob wrote/assisted with directly** (if using Bob for app code too, not just content generation): keep those diffs/commits separately identifiable — e.g. commit messages or a `bob-assisted/` note — so they're easy to point to in the submission.

## Logistics
- Save screenshots into a dedicated folder, e.g. `evidence/bob-sessions/`, named by milestone (`01-kickoff.png`, `02-hotspot-config-merge.png`, etc.) so they're easy to pick from when filling the submission form.
- Do this at the moment each milestone happens — bolt it onto the workflow itself (e.g., screenshot immediately after each hotspot's Bob session completes), not as a separate "screenshot pass."
- Keep a running one-line log (timestamp + what was captured) alongside the screenshots — makes writing the submission's "Application of Technology" section much faster afterward.

## Not needed until Sept 25
Nothing here is actionable before Bob 2.0 access opens — this is the checklist to have ready, not to execute yet.
