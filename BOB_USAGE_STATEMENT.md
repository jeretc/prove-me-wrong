# IBM Bob Usage Statement

**Prove Me Wrong** uses IBM Bob 2.0 as the core content-generation engine for its entire onboarding-quiz experience. Bob is not a bolted-on feature, it is the reason the product can exist at all: every question, answer, citation, and follow-up shown to the user was generated by Bob reading the real, live axios/axios repository, not written by hand or pulled from documentation.

**How Bob was used**

We identified 8 real behavioral "hotspots" in axios (config merge order, interceptor execution order, redirect credential stripping, cancellation, XSRF auto-attach, response size limits, transform pipeline replacement, and proxy tunneling) as topics worth curating. For each one, Bob IDE was given the topic and asked to independently: write a quiz question, work out the ground-truth answer, and cite the exact file and line in the current source that proves it, using its own repository exploration (Agent mode reading the cloned axios source directly, not prior training knowledge). We repeated this for a gentler follow-up question per topic, shown when a user guesses wrong, and again for a session-summary synthesis task that turns a completed session into a personalized recap. In total, 17 separate Bob tasks were run, using roughly 2.6 of our 40 allocated Bobcoins, well under budget.

**Why this matters for the product's own thesis**

While building, Bob made a genuine reasoning error three separate times, independently, on the same topic (interceptor execution order): it claimed request interceptors run in reverse-registration order, when tracing the actual code shows they run in registration order. We caught this by doing exactly what our product asks its own users to do: never trust the answer, verify it against the real file and line. Each mistake was traced by hand through the cited source before being corrected. This was not a setback, it validated the entire premise of the app: even a powerful, repository-aware AI benefits from citation-grounded verification rather than blind trust, and a workflow built around "prove it, don't just claim it" catches errors that a plain Q&A chatbot would silently pass along.

**Division of labor**

Bob generated 100% of the domain content: every question, every ground-truth answer, and every citation used in the live application. The surrounding product, the Next.js interview flow, the guess-evaluation logic, the adaptive follow-up branching, and the visual design, was built around that content to deliver it as a coherent, interactive onboarding experience. This mirrors the product's own value proposition: Bob supplies deep, repository-grounded reasoning; the application supplies the workflow, pedagogy, and verification loop that turns that reasoning into a trustworthy learning tool rather than a wall of AI-generated text.
